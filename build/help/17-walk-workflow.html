Do the same steps again: workflows

A workflow chains tools together: the files one step writes go straight into the next, so a job of several steps runs in one go, and can run again on another file. This walkthrough runs one of the example workflows, runs it again on a file of your own, changes it, and makes a workflow from tools you’ve already run.

1 · The workflows

Workflows, at the top of the Tools tab, lists your workflows, the examples and the runs so far.

2 · Run one

Open A person’s own TP53. The run page lists the workflow’s inputs, each with a file already chosen, and the folder for the results. Press Run it.

The steps run one after another, each with the files the steps before it wrote. As each finishes, it says what it did; open it to see its command and what it printed. A step whose files a failed step should have written doesn’t run, and says so.

3 · What a run leaves

Each run has a folder of its own, ~/results/workflow/input, here ~/results/a-person-s-own-tp53-pictures-and-sequences/hg002-chr17. It holds the files the steps wrote, and two more:

  • workflow-run.json, the record of the run: the files given, each step’s command, what it printed and what it wrote. Open it to see the run again, step by step.
  • commands.sh, the steps as terminal commands. bash commands.sh in the terminal runs them again, and on your own computer they run as they are, once the packages are installed.

Open the steps as a notebook, under a finished run, turns its steps into a notebook of Python, a cell for each step, to change and run a piece at a time.

4 · Run it on another file

Run the same workflow on any gpxil file with a sample: choose it in the first input. If you made ~/genomes/HG002_TP53.gpxil.tif in Turn someone’s VCF into a gpxil file, try it on that.

The settings that come from a file – the region of a picture, say – are worked out for each file, as the Tools tab works them out, unless the workflow gives them.

5 · Change it

An example can’t be changed, but you can edit a copy, which is saved in ~/workflows. The editor draws each step as a box: its input files on the left, the files it writes on the right.

  • Click a box to see its settings beside the boxes, and change them: to make pictures of BRCA1 as well, put TP53 BRCA1 in the Genes of the gpxil2pxil step.
  • Drag from a file a step writes (the dot on the right of its box) to an input of another step to connect them. Only files of a kind the input takes will connect.
  • The + by a file offers the tools that read it, and adds the one you choose, connected.
  • + Input file adds an input to the workflow, and + Add a step a tool. Tidy lays the boxes out in columns. The editor saves as you go; the download button saves the workflow file, to keep or to send to someone.

A step with a problem – an input not connected, say, or an input of the workflow that nothing reads – is marked on its box. Click an empty part of the editor to see the workflow’s own settings, its name and what it does, with its problems listed under Checks. It won’t run until they’re fixed.

6 · A workflow from what you’ve done

If you’ve just run a few tools by hand, one after another, Make one from the tools you’ve run turns them into a workflow: the files you started from become its inputs, and a file that one tool wrote and the next read becomes a connection. The settings you changed are kept.
