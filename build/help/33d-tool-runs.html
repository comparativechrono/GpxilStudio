Find runs of a composition

gpxil runs finds the stretches of a genome made only of some bases: of A and G, as Guenter Albrecht-Buehler’s pure GA-sequences are, of C and T, of A and T, or of one base. It reads the reference plane a piece at a time, so a chromosome takes a few seconds, and writes the runs as a BED file, ready for the other tools that look for patterns: stack them, count their substitutions, or add them to the genome as a plane.

What a run is

its bases
Given in IUPAC letters (The codes): AG or R for purines, CT or Y for pyrimidines, AT or W, CG or S, A for runs of one base, and so on. A base of the reference belongs if its own letter does: an R belongs to AG, an N only to ACGT. Soft masking doesn’t matter.
as long as it can be
A run is maximal: the bases either side of it don’t belong, or there are none. Runs shorter than the shortest you ask for are left out: 51 bases by default, since Albrecht-Buehler’s pure GA-sequences are more than 50 bases long.
on both strands
The other strand’s bases are the complements of this one’s, so a run of A and G there is a run of C and T here. With both strands, those are found too, and written with strand -. A set that is its own complement, such as AT or CG, has the same runs on both strands: they are written once, without a strand (.).
in a file of windows
Windows that overlap or touch are read as one stretch, at the chromosome’s positions, and where a stretch ends, a run ends with it.

The form

The gpxil file
Any gpxil file with its reference plane, or one without it, with its reference given (a field for it appears).
Of these bases
The set, in IUPAC letters: AG to begin with.
At least this many bases
The shortest run to keep: 51.
On both strands
Ticked: the set’s runs on the other strand too.
Regions
One or more, separated by spaces: a contig, or CONTIG:START-END counting from 1. Regions that overlap are read once, as one. Empty: every contig.
Save as
A BED file, named after the genome and the set: ~/results/HG002_chr17_AG_runs.bed.

What it gives

A BED file, a run a line: its contig, its start (counting from 0) and end, the set (AG), its length as the score (up to 1000, the most a BED score can be) and its strand. The tool also says how many runs there are on each strand, how many bases they cover, how long they are – the median, the 90th and 99th percentiles and the longest – and how many there are a megabase of A, C, G and T. Stack them and Their substitutions take the BED file on to the next tools.

Chromosome 17’s pure GA-sequences

Chromosome 17 of GRCh38 has 1,561: 739 runs of A and G on the + strand and 822 on the − strand (runs of C and T on this one), 140,621 bases in all, half of them 71 bases long or less and the longest 574: 18.8 a megabase. By chance, with half the bases purines, a stretch of 51 bases would be all purines once in 2⁵¹ – about 2 × 10¹⁵ – so the whole genome would have none. Albrecht-Buehler counted 19,139 in the human genome of 2008, and 1,667 on chromosome 1; GRCh38 has 22,726 runs of A and G and 22,955 of C and T, as many on each strand as Chargaff’s second rule expects (Strand symmetry). Pure GA-sequences follows them through the other tools.

In the terminal

gpxil runs /data/examples/HG002_chr17.gpxil.tif --of AG --both-strands -o ~/results/GA.bed
gpxil runs /data/examples/HG002_chr17.gpxil.tif chr17:7,661,779-7,687,546 --of A --min 15
gpxil runs /data/examples/HG002_chr17.gpxil.tif --of W --min 200 -o ~/results/AT-rich.bed --json

Without -o, the runs go to the terminal; --json gives the counts to programs; --reference gives the reference of a file written without one.

In Python

from gpxiltools import GpxilFile
from gpxiltools.runs import RunFinder

with GpxilFile("/data/examples/HG002_chr17.gpxil.tif") as g:
    runs = list(RunFinder(g, of="AG", min_length=51, both_strands=True).runs())
print(len(runs), "runs; the longest:", max(runs, key=lambda r: r.length))
print(sum(r.strand == "-" for r in runs), "on the - strand")

Each run is a Run(sequence, start, end, strand), counting from 0; RunFinder(g, [g.region_of("chr17:1-1000000")], …) looks only there, and write_bed writes runs as the command does.
