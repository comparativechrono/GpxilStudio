Make a working copy (subset)

gpxil subset copies some contigs of a gpxil file, and if you like only some of its planes, into a new file: a working copy, such as one chromosome out of a whole genome. Each contig of a gpxil file stands on its own – its pages and its entry in the metadata – so nothing needs encoding again: the pages’ strips are copied as they are stored, without being decoded. It is quick, needs little memory, and works as well on a file you added to this browser, or one on the web. Given a region, such as a gene, it cuts that stretch out as a window, which keeps the chromosome’s positions.

What it is for

  • One chromosome out of a whole genome. A person’s whole genome is about 850 MB as gpxil; chromosome 17 is 25 MB of it. Make the copy on your own computer and add it here (On your own computer), or add the whole genome here: the copy reads only the pages it copies.
  • A smaller file. The reference plane is most of a file: without it, HG002’s chromosome 17 goes from 24.6 MB to 1.9 MB. The contigs keep the checksums of their reference, so any tool can be given it again (each tool has a field for it, and the Viewer borrows GRCh38’s from the Gpxil browser). Leaving out genotype quality and read depth (gq, dp) saves a little more.
  • A gene, or any stretch, as a file of its own. A region becomes a window: a contig that holds just those bases and says where they lie on the chromosome, so every tool, and the Viewer, still gives their positions as the chromosome’s. TP53 and 100,000 bases either side is 76 kB (12 kB without its reference plane), out of the 24.6 MB of chromosome 17. Only the strips that hold the region are read, so it takes a second, from a file here or on the web – the way to send someone a gene.
  • The reference put back. A file written without its reference plane gets it again from a reference you give, which is checked against the checksums.
  • Another compression. A file made elsewhere with Zstandard, which the browser can’t read, encoded again with deflate (on a computer with the imagecodecs package).

The form

The gpxil file
Any gpxil file: yours, an example, or a chromosome of GRCh38.
Contigs
The contigs to copy, by name, separated by spaces or commas (chr17, or chr17 chr21); 17 finds chr17 too. Empty: all of them (unless you give regions). The copy keeps them in the file’s order. In a file of windows, a chromosome’s name copies all its windows.
Regions, cut out as windows
Regions such as chr17:7,661,779-7,687,546, counting from 1 and including both ends, separated by spaces: each becomes a window. The positions are the chromosome’s, in a file of windows too, where a region is cut out of the window that holds it.
Planes
All the planes each contig has, or some of them: without genotype quality and read depth; the reference, genotype and flags only; or the reference only, without the sample. A plane a file doesn’t have is left out.
Leave out the reference plane
As gpxil encode --no-ref: a file about a hundred times smaller.
Put its reference plane back, from
Only for a file written without one: a FASTA file, or a gpxil file with its reference plane, such as a chromosome of GRCh38 from /data/grch38.
Compression
As it is (the default), so that the strips are copied without decoding, or encoded again.
Save as
A file name ending in .gpxil.tif, in ~/genomes unless you choose otherwise.

A window holds exactly what the whole chromosome holds over its bases: every plane, the insertions that follow its bases, and its phase sets – and no more, so a deletion that runs past its end, say, stops at its end. It won’t leave out the phase sets (ps) of a contig or window with more than one, because its phased calls would then read as one phase set.

What it writes

A gpxil file with the contigs and planes chosen, each contig with its entry in the metadata – its checksums, how it was encoded, how many records – and a record, subset, of the file it came from. A window is named for the stretch it holds, such as chr17:7661779-7687546, and its entry says where it lies, "window": {"of": "chr17", "start": 7661778, …} with the chromosome’s length and checksums; a file with windows follows version 0.3 of the specification (The gpxil format). It says how many contigs, bases and megabytes it wrote, and whether the strips were copied as stored. Check it, look at it in the Viewer, or count what it holds.

In the terminal

gpxil subset /data/examples/HG002_chr17.gpxil.tif chr17 --no-ref -o ~/genomes/HG002_chr17.noref.gpxil.tif
gpxil subset ~/genomes/HG002_chr17.noref.gpxil.tif --planes ref,gt,flags --reference /data/grch38/chr17.gpxil.tif -o ~/genomes/HG002_chr17.three-planes.gpxil.tif
gpxil info ~/genomes/HG002_chr17.three-planes.gpxil.tif
gpxil subset /data/examples/HG002_chr17.gpxil.tif chr17:7,661,779-7,687,546 -o ~/genomes/HG002_chr17_7661779-7687546.gpxil.tif
gpxil info ~/genomes/HG002_chr17_7661779-7687546.gpxil.tif
gpxil fasta ~/genomes/HG002_chr17_7661779-7687546.gpxil.tif --which 1 --region chr17:7676101-7676200

On your own computer, chromosome 17 out of a whole genome: gpxil subset HG002.gpxil.tif chr17 -o HG002_chr17.gpxil.tif. The input can be a URL too, and then only the pages copied are downloaded – for a window, only the strips that hold it.

In Python

from gpxiltools import GpxilFile
from gpxiltools.subset import subset

summary = subset("/data/examples/HG002_chr17.gpxil.tif", "/home/user/genomes/HG002_chr17.noq.gpxil.tif",
                 ["chr17"], planes=["ref", "gt", "flags", "ps"])
print(summary)

# TP53 as a window: its positions are still chromosome 17's
subset("/data/examples/HG002_chr17.gpxil.tif", "/home/user/genomes/TP53.gpxil.tif", ["chr17:7,661,779-7,687,546"])
with GpxilFile("/home/user/genomes/TP53.gpxil.tif") as g:
    w = g.contigs[0]
    print(w, g[w].parent, g[w].start)                 # chr17:7661779-7687546 chr17 7661778
    c, s, e = g.locate("chr17", 7676153, 7676154)    # chr17:7,676,154, in the window
    print(c.read("gt", s, e))

GpxilWriter.copy_contig does the copying, a contig at a time, and GpxilWriter.cut_contig cuts a window, for your own programs.
