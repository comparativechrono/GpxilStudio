A whole genome without running out of memory

A human genome is 3.1 billion bases. As one byte a base, a single plane of it is 3.1 GB in memory, more than Python in a browser can use, although the file that holds it is under 1 GB. Yet the studio opens a whole genome at once, because it never reads more of a file than it needs. This walkthrough shows how, and how to write your own code the same way.

1 · Read regions, not files

Each plane of a gpxil file is stored in strips of whole rows: 32 rows of 8,192 bases, 262,144 bases a strip, in a file made with the default layout. Reading a region decompresses only the strips that hold it. A gene is one strip or two, so reading it costs the same in a file of one chromosome as in a file of the whole genome.

The studio adds one more step. A file of 8 MB or more is never copied into Python’s memory: Python reads it where the browser keeps it, or from the web, a piece at a time. The chromosomes of GRCh38 in /data/grch38 are read from the Gpxil browser’s site like this, a megabyte at a time, as they’re needed. And the Viewer and the Files tab read gpxil files without Python at all.

2 · A chromosome, a piece at a time

To go through a whole chromosome, read it in pieces and keep only what you work out from each. This finds the GC content of each megabase of chromosome 21, read from the web: at any moment, Python holds one megabase.

import numpy as np
from gpxiltools import GpxilFile
from gpxiltools import codes as C

c = GpxilFile("/data/grch38/chr21.gpxil.tif")["chr21"]
step = 1_000_000
gc = []
for a in range(0, c.length, step):
    base = C.ref_base_nibble(c.read("ref", a, min(a + step, c.length)))
    acgt = np.isin(base, (C.BASE_A, C.BASE_C, C.BASE_G, C.BASE_T)).sum()
    gc.append(np.isin(base, (C.BASE_G, C.BASE_C)).sum() / acgt if acgt else np.nan)
gc = np.array(gc)
print(f"{c.length:,} bases in {gc.size} pieces, {np.isnan(gc).sum()} of them all N")
print(f"GC from {np.nanmin(gc):.1%} to {np.nanmax(gc):.1%}, highest in megabase {np.nanargmax(gc) + 1}")

Chromosome 21’s first five megabases are all N – the short arm, which GRCh38 doesn’t spell out – and its GC content runs from 34.6 % to 53.0 %, highest near the end of its long arm. A loop over all the chromosomes of a genome works the same way, contig by contig: for c in g:. gpxil stats goes through a file like this to count what it holds (section 4).

3 · Files without the reference, which borrow it

A person’s genome as a gpxil file is mostly their reference: the same bases for everyone. Written without the reference plane (gpxil encode --no-ref), it is a small fraction of the size, and names its reference by checksums. Open it with the reference, and gpxiltools reads just the region you ask for from the reference, after checking that its checksums match. The Viewer does the same by itself for a file made on GRCh38.

from gpxiltools import GpxilFile
from gpxiltools.encode import encode
from gpxiltools.export import haplotype_sequence

encode("/data/grch38/chr17.gpxil.tif", "/home/user/genomes/HG002_TP53.noref.gpxil.tif",
       vcf="/data/examples/HG002_TP53.vcf", callable_bed="/data/examples/HG002_TP53.bed",
       planes=["gt", "flags"], include_ref=False)
with GpxilFile("/home/user/genomes/HG002_TP53.noref.gpxil.tif", reference="/data/grch38/chr17.gpxil.tif") as g:
    c = g["chr17"]
    print(c.planes, "plus the borrowed reference:", c.has("ref"))
    print(haplotype_sequence(c, 1, 7_676_100, 7_676_200).decode())

4 · A working copy, and what it holds

To work on part of a big file, make a working copy of it: gpxil subset copies the contigs you choose, and the planes you choose, into a new file. It copies the pages’ strips as they are stored, without decoding them, so it takes little memory and little time, even from a whole genome or a file on the web. Leaving out the reference plane makes the copy about a hundred times smaller: HG002’s chromosome 17 goes from 24.6 MB to 1.9 MB, and the Viewer borrows the reference from GRCh38 as before.

gpxil subset /data/examples/HG002_chr17.gpxil.tif chr17 --no-ref -o ~/genomes/HG002_chr17.noref.gpxil.tif
gpxil stats ~/genomes/HG002_chr17.noref.gpxil.tif

gpxil stats then counts what the copy holds, a piece at a time: 86.9 % of chromosome 17 called, 54,935 heterozygous and 34,713 homozygous substitutions, and the insertions, deletions, phasing, quality and depth (Count what a file holds). Without the reference plane it counts all but the reference’s bases and Ti/Tv; give it --reference /data/grch38/chr17.gpxil.tif for those. The Viewer counts the same for the region in view, under its key.

5 · What uses memory, and what doesn’t

  • Doesn’t: opening a file, its metadata, the Viewer, the Files tab, reading a region, a loop over pieces, gpxil info, gpxil vcf and gpxil fasta (which write as they go), gpxil validate and gpxil stats (which read a piece at a time), gpxil subset (which copies a strip at a time).
  • Does: gpxil encode, which holds each contig’s planes whole while it works: about 6 bytes a base with the planes gt and flags, so half a gigabyte for chromosome 17 and about 1.5 GB for chromosome 1, more than a browser tab may have. In the browser, encode one chromosome at a time (Only these contigs, or --contigs), and the biggest chromosomes, or a whole genome, on your own computer (section 6). Also a whole plane read at once (c.read("gt") on chromosome 1 is 249 MB), and big pictures, which is why the tools stop at 25 million bases a picture in the browser.
  • Keep arrays small: uint8 as they come, not converted to 64-bit numbers. del big arrays you’ve finished with, and if Python gets slow or stops with a MemoryError, restart it (the Notebook’s Restart, or the Python pill in the Tools tab): your files are safe, only Python’s variables are lost.

6 · The whole genome on your own computer

On your own computer, memory is less tight and the files can be local. The Gpxil browser offers the whole of GRCh38 as one gpxil file, 848.5 MB, which every command here can use as a reference or read like any other:

curl -LO https://github.com/comparativechrono/Gpxil-browser/releases/download/grch38-ensembl116/GRCh38.gpxil.tif
curl -LO https://github.com/comparativechrono/Gpxil-browser/releases/download/grch38-ensembl116/GRCh38.gpxil.tif.sha256
sha256sum -c GRCh38.gpxil.tif.sha256          # on a Mac: shasum -a 256 -c GRCh38.gpxil.tif.sha256
gpxil info GRCh38.gpxil.tif
gpxil encode GRCh38.gpxil.tif -v my.vcf.gz --callable my.bed --no-ref -o my.gpxil.tif
gpxil stats my.gpxil.tif --reference GRCh38.gpxil.tif
gpxil subset my.gpxil.tif chr17 -o my_chr17.gpxil.tif   # a working copy to add to the studio

(curl -C - -LO … carries on with a download that was interrupted.) On your own computer says how to install the programs there.
