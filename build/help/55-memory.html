Big files and memory

A gpxil file of a chromosome is tens of megabytes, and of a whole genome nearly a gigabyte, while a browser tab has a few gigabytes at most – and Python less. So the studio never copies a big file whole: everything reads just the part it needs. This page explains how, what the limits are, and how to stay within them. A whole genome without running out of memory walks through it with examples.

The format makes it possible

Each plane of a gpxil file is stored in strips of 32 rows – 262,144 bases – each compressed on its own (The gpxil format). A reader opens a file by reading its metadata and the TIFF’s list of pages, a few kilobytes, and then decompresses only the strips a region needs. A gene is a strip or two, whether the file holds one chromosome or the whole genome.

Without Python: the Viewer and the Files tab

The Viewer and the Files tab read gpxil files themselves, in the page: the list of pages, then only the strips they show, decompressed by the browser. A file in your home folder is read where the browser keeps it, and a file on the web, such as GRCh38’s chromosomes, with HTTP range requests, which fetch just those bytes. So any gpxil file opens at once. The Viewer draws at most 4 million bases at a time.

Python: big files are lent, not copied

Python runs in a web worker – Pyodide, CPython compiled to WebAssembly – with a memory of its own. Small files are copied into it before a cell or a command runs, and the changes copied back afterwards. Files of 8 MB or more never are:

  • Your big files stay where the browser keeps them, and are lent to Python as files it reads a piece at a time.
  • The examples and the GRCh38 reference are read from the web a megabyte at a time, as Python asks for them, with HTTP range requests.
  • A big file that Python writes, such as a new gpxil file, is handed to the browser to keep when the command ends, and Python’s copy is freed.

gpxiltools reads only the strips of the region it is asked for, so gpxil info on chromosome 1 reads a few kilobytes, and a gene a few hundred. In the experiment that led to the studio, the whole genome as one file, 809 MB, opened in 72 MB of Python’s memory.

Working copies

To work on part of a big file, copy that part: gpxil subset makes a new gpxil file of the contigs you choose, and of the planes you choose, copying the pages’ strips as they are stored, so it takes about one strip of memory however big the file (Make a working copy). A chromosome of a whole genome is a few per cent of it, and without the reference plane a hundredth of that again. gpxil stats counts what a file holds a piece at a time in the same way (Count what a file holds).

Keeping your own code small

  • Read regions – c.read(plane, start, end) – not whole planes, and go through a chromosome in pieces: a strip (262,144 bases) or a megabase at a time.
  • Keep arrays as they come, 8-bit (uint8): chromosome 1’s plane as 64-bit numbers is 2 GB instead of 249 MB. Count with np.count_nonzero rather than building big arrays of results.
  • del big arrays you’ve finished with. Python’s memory doesn’t shrink, but what is freed is used again.
  • If Python stops with a MemoryError, or stops answering, restart it: Restart in the Notebook, or the Python pill in the Tools tab. Your files are safe; only Python’s variables are lost.

This counts HG002’s substitutions on chromosome 17, a strip at a time, so that it never holds more than a quarter of a megabyte of the plane:

import numpy as np
from gpxiltools import GpxilFile
from gpxiltools import codes as C

with GpxilFile("/data/examples/HG002_chr17.gpxil.tif") as g:
    c = g["chr17"]
    step = 32 * c.width                    # one strip: 262,144 bases
    het = hom = pieces = 0
    for a in range(0, c.length, step):
        gt = c.read("gt", a, min(a + step, c.length))
        h1, h2 = C.hap1(gt), C.hap2(gt)
        s1, s2 = np.isin(h1, C.HAP_SUB_CODES), np.isin(h2, C.HAP_SUB_CODES)
        hom += np.count_nonzero(s1 & s2 & (h1 == h2))
        het += np.count_nonzero((s1 & (h2 == C.HAP_REF)) | (s2 & (h1 == C.HAP_REF)) | (s1 & s2 & (h1 != h2)))
        pieces += 1
print(f"{het:,} heterozygous and {hom:,} homozygous substitutions, read in {pieces} pieces")

The browser’s storage

Your files are kept in the browser’s storage for the site (Where your files are kept). A single file bigger than 1 GB is there while the page is open but isn’t kept, so download it before you leave. The studio warns when your files come to more than 2,000 MB, and browsers limit what a site may keep, usually to a share of the free disk space. A whole genome with one person fits, but not many: for many people, keep files without the reference plane (--no-ref), a small fraction of the size, which borrow GRCh38 from the web when they need its bases.
