Workflows

A workflow is a set of the Tools tab’s tools joined together, so that each reads the files the ones before it wrote. Draw one in the editor, start from an example, or make one from the tools you’ve run; then run it on the same files again, or on new ones. They work like the workflows of Galaxy. The walkthrough takes you through one.

Inputs and steps

A workflow has inputs, the files it is given when it runs, and steps, each a tool. Each input says which kinds of file it takes – a gpxil file, a VCF, a reference (FASTA or gpxil), a BED file, a GTF file, pxil pictures – and can suggest a file, which the run page offers. An input can be optional, for a file a step can do without, such as a VCF’s BED file of callable regions.

Every tool can be a step except The palettes, which reads and writes nothing. What’s in a gpxil file and Check a gpxil file write no files, so nothing can follow them, but they say what they found in the run. Genes, transcripts and proteins as pxil pictures writes a set of files, which goes as a whole into a step that reads several, such as pxil pictures → FASTA.

The editor

  • Each step is a box, with its input files on the left and the files it writes on the right. Drag from a file’s dot to an input of another step to connect them; only files of a kind the input takes will connect, and never in a loop.
  • The + by a file lists the tools that can read it, and adds the one you choose, connected to it.
  • Click a box to see its settings beside the boxes. A step’s settings are its tool’s form, without the files, which come from the connections, and without where to save, which the run decides.
  • + Input file and + Add a step add boxes; Tidy arranges them in columns, inputs on the left. Changes are saved as you make them.
  • Click an empty part of the editor for the workflow’s own name and description, and its Checks: anything that stops it running, such as an input not connected.

Running

The run page asks for a file for each input, and for the folder for the results, by default ~/results/workflow/first input. Press Run it, and the steps run one after another, in an order in which each runs after the steps it reads from. Each step shows its state as it goes, and when it’s done, what it did; open it for its command, what it printed and the files it wrote. If a step fails, the steps that need its files are skipped, and the rest still run. Stop stops the run after the step that is running.

A step that would write a file with the same name as one an earlier step wrote writes into a folder of its own, so nothing is overwritten.

What a run leaves

  • The files the steps wrote, in the run’s folder.
  • workflow-run.json, the record of the run, which opens as the run’s page, step by step.
  • commands.sh, the steps as terminal commands, to run again with bash commands.sh, here or on your own computer.
  • On the run’s page, Open the steps as a notebook makes a notebook with a cell of Python for each step.

The workflow file

A workflow is a file of its own, ~/workflows/name.workflow.json: JSON that lists the inputs and steps, the settings of each step that differ from the tool’s, and the connections. Download it from the editor to keep it or to send it to someone; Add a workflow file… on the Workflows page adds one you’ve been given. The examples, in /data/examples/workflows, can’t be changed, but Edit a copy makes one of your own.
