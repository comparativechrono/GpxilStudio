Draw a region as a picture

gpxil render draws a region of a gpxil file as a picture, one pixel (or a square of pixels) a base: a PNG for the screen, or a TIFF in RGB or in CMYK for print. The colours come from a palette when the picture is drawn; the file holds codes, not colours, which is why the same file gives exact colours on a screen and in ink.

The form

The gpxil file
Any gpxil file with a reference plane, or one written without it together with its reference (below).
Region
A contig, or CONTIG:START-END, counting from 1 and including both ends, such as chr17:7,661,779-7,687,546. When you choose a file, the form suggests TP53 for a file with chromosome 17, or else a contig. In the browser, a picture may have up to 25 million bases.
Show
reference: the reference’s bases. genotype: the person’s two bases at once, a heterozygous base as the mix of its two colours, a base deleted from both as paper. haplotypes: the two haplotypes in two rows of pixels for each row of bases, haplotype 1 above. variants: the faded reference with the variants on it: heterozygous orange, homozygous red, a deletion dark, a base followed by an insertion green, no call grey, a complex variant purple. A file without a sample can only show the reference.
Colours
classic, okabe-ito, gpxi or process (The palettes).
Bases per row
By default the file’s own width (8,192); for a region of 200,000 bases or fewer, the form suggests 256. A width equal to a repeat’s period lines the repeat up in columns.
Pixels per base
Each base as a square of this many pixels a side; the form suggests 4 for a region of 50,000 bases or fewer, so that each base can be seen. The whole picture may have up to 64 million pixels in the browser.
Layout
rows, like text, or a Hilbert curve, which folds the region into a square so that bases next to each other in the genome stay next to each other in the picture. Not for the haplotypes view.
Picture
PNG for the screen; TIFF in RGB; or TIFF in CMYK for print, with each colour given directly in the palette’s ink values.
Dots per inch to record
The resolution written into the picture, which tells printing software how big to print it.
Mark where insertions are
In the haplotypes view, a base that an insertion follows is magenta.
Its reference
Only for a file written without its reference plane: the same reference, a FASTA file or a gpxil file with its reference plane. For GRCh38, the form fills in the chromosome from /data/grch38, and gpxil checks it against the file’s checksums.
Save as
The picture, named after the file, the region and the view, in ~/results.

What it writes

One picture, and a line giving its size in pixels and the region. A PNG is an indexed-colour picture: small, and exact.

In the terminal

gpxil render /data/examples/HG002_chr17.gpxil.tif chr17:7661779-7687546 -o ~/results/TP53.png --mode variants --width 256 --scale 4
gpxil render /data/examples/worked-example.gpxil.tif chrT -o ~/results/worked-example.png --mode haplotypes --width 4 --scale 16 --mark-insertions
Option
FILE REGION -o PICTUREthe file, the region, and the picture to write: .png, or .tif
--mode reference|genotype|haplotypes|variantsthe view (genotype if you don’t say)
--palette NAMEclassic, okabe-ito, gpxi or process
--width N, --scale Nbases per row; pixels per base, each way
--layout raster|hilbertrows, or a Hilbert curve
--cmyk, --dpi Na CMYK TIFF for print; the resolution to record
--mark-insertionsin the haplotypes view, mark the bases insertions follow
--reference FILEthe reference, for a file written without one

In Python

from gpxiltools import GpxilFile
from gpxiltools.render import render

with GpxilFile("/data/examples/worked-example.gpxil.tif") as g:
    picture = render(g["chrT"], mode="haplotypes", bases_per_row=4, mark_insertions=True)
print(picture.shape)          # 6 rows of pixels: 2 for each of the 3 rows of bases
print(picture.index)          # palette indices
picture.scaled(16).save_png("/home/user/results/worked-example-haplotypes.png")
