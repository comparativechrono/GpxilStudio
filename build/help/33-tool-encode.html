Make a gpxil file (encode)

gpxil encode turns a reference genome, and one person’s variants from a VCF, into a gpxil file. Every base of the reference becomes a pixel of the ref plane, and every call in the VCF is written base by base into the gt and flags planes, as the specification sets out, so that any two programs that follow it make the same planes from the same VCF.

The form

The reference genome
A FASTA file (plain, gzip or bgzip), or a gpxil file with its reference plane, such as a chromosome of GRCh38 from /data/grch38. From a gpxil file, only the contigs you encode are read; a FASTA file is read a record at a time.
The person’s variants (VCF)
A VCF (or .vcf.gz) with the person’s genotypes, version 4.2 or later. Without one, the file holds the reference alone.
Sample
For a VCF of several people, the column to encode; by default, the first.
Regions called with confidence (BED)
Bases outside these regions are UNKNOWN – not called – rather than taken to be the reference. Give one whenever you have it: a VCF of variant sites says nothing about the bases it doesn’t list. A BED file with the same name as the VCF is chosen for you.
Only these contigs
Contigs of the reference, separated by commas, such as chr17. By default, all of the reference’s contigs; one with no calls in the VCF, and no callable regions, is stored as reference only.
Only these regions, as windows
Instead of contigs, regions such as chr17:7,600,001-7,750,000, counting from 1, separated by spaces. Each becomes a window (gpxil 0.3): a contig that holds just those bases and keeps the chromosome’s positions. Only the calls that reach into a region are applied, and only the reference’s bases there are read, so it takes a second or two and little memory – and the window holds just what the same stretch of the whole chromosome would. HG002’s variants around TP53, 150,000 bases, make a file of 50 kB (7 kB without the reference plane).
Planes from the VCF
gt and flags (the default here), or all the VCF has: also its genotype qualities (gq), read depths (dp) and phase sets (ps), which take as much memory again.
Leave out the reference plane
A much smaller file, which names its reference by the checksums of its sequences. Reading its bases then needs the reference too.
Sex chromosomes
XY: chromosomes X and Y outside the pseudo-autosomal regions of GRCh38 have one copy, so haplotype 2 is ABSENT there. XX records the sex without changing anything.
The reference’s name
Such as GRCh38, recorded in the metadata. A gpxil file as the reference gives its own.
Bases per row of each page
The layout of the pictures, 8,192 by default. It changes nothing in the data – any reader can re-wrap a plane – but small rows make small strips, so a region reads quickly.
Compression
Deflate, which every TIFF reader supports, or none.
Colours stored for image viewers
The palette of the colour map stored with the ref plane, so that an ordinary image viewer shows the file in colour. It doesn’t change the data.
Save as
The new file, ~/genomes/name.gpxil.tif by default.

What it writes

One gpxil file, and a line saying how many contigs and bases it holds, how big it is and how long it took. Under that may come notes, such as VCF contigs that the reference doesn’t have (skipped), or calls that conflict with each other (the later one wins, and the metadata counts them). How a VCF becomes gpxil explains exactly how each kind of call is written.

It holds each contig’s planes whole while it works – about 6 bytes a base with the planes gt and flags – so the biggest contig sets the memory needed. HG002’s variants on chromosome 17 (83 million bases) take about half a gigabyte, and about a minute in the browser (12 seconds on a computer’s own Python); chromosome 1 (249 million bases) would need about 1.5 GB, more than a browser tab may have. So in the browser, encode one chromosome at a time, with Only these contigs, and encode the biggest chromosomes, or a whole genome, on your own computer (On your own computer). A window needs memory for its own bases only, so a gene, or a few megabases around it, is quick anywhere.

In the terminal

gpxil encode /data/examples/worked-example.fa -v /data/examples/worked-example.vcf --width 4 -o ~/genomes/worked-example.gpxil.tif
gpxil encode /data/grch38/chr17.gpxil.tif -v /data/examples/HG002_TP53.vcf --callable /data/examples/HG002_TP53.bed --planes gt,flags --no-ref -o ~/genomes/HG002_TP53.noref.gpxil.tif
gpxil encode /data/grch38/chr17.gpxil.tif -v /data/examples/HG002_TP53.vcf --callable /data/examples/HG002_TP53.bed --planes gt,flags --region chr17:7,600,001-7,750,000 -o ~/genomes/HG002_TP53_chr17_7600001-7750000.gpxil.tif
Option
-v VCF, -s SAMPLEthe variants, and which sample
--callable BEDthe regions called with confidence
--haploid BED, --haploid-contig NAMEregions, or whole contigs, where the person has one copy
--sex XYone copy of chrX and chrY outside the pseudo-autosomal regions
--contigs A,B, --ucsc-nameswhich contigs; rename 1–22, X, Y and MT to chr1 … chrM
--region CONTIG:START-ENDa window of the reference instead of whole contigs; give it again for more
--no-ref, --planes gt,flagsleave out the reference plane; which planes from the VCF (without --planes, the command takes gq, dp and ps too when the VCF has them, unlike the form)
--width N, --compression NAME, --level Nthe layout and the compression (on your own computer, also zstd, lzw, lzma and packbits, with the imagecodecs package)
--palette NAME, --reference-name NAMEthe colours for image viewers; the reference’s name
--invalid-to-nturn characters of the FASTA that aren’t IUPAC codes into N, rather than stopping
--bigtiffBigTIFF from the start; otherwise gpxil switches to it by itself if the file might pass 4 GB

In Python

from gpxiltools.encode import encode

summary = encode("/data/examples/worked-example.fa", "/home/user/genomes/worked-example.gpxil.tif",
                 vcf="/data/examples/worked-example.vcf", width=4, reference_name="worked example")
print(summary)
