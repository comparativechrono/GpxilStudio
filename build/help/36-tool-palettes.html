The palettes

A gpxil file holds codes, not colours. A palette turns them into colours when a picture is drawn: into screen colours (sRGB) for a PNG, or directly into ink (CMYK percentages) for print, so neither is converted from the other. gpxil palettes lists them.

classic
The colours of the original gpxil notebooks, and the default.
A red C blue G green T yellow N near-black
okabe-ito
Colours that people with any common colour-blindness can tell apart.
A bluish green C blue G orange T vermilion N near-black
gpxi
The grey levels of Albrecht-Buehler’s genome pixel images, after which gpxil is named.
A black C dark grey G white T light grey N pale blue
process
One pure printing ink for each base, which prints most faithfully.
A cyan C magenta G yellow T black N grey (35 % black)

Every palette also has a colour for “no base” (paper), and one for N (an unknown base) that no base or mix of bases has: near-black in classic and okabe-ito, whose mixes include greys, so that a heterozygous base never looks unknown. Neither is paler in a soft-masked repeat. The other codes are worked out from the four bases: an ambiguous base, or a heterozygous one in the genotype view, is the mean of its bases’ colours (in the process palette, the inks overprint), and a base in a soft-masked repeat is faded 45 % towards white (not in gpxi, whose greys need all their levels).

With the process palette, the code of a base is its ink: the four bits of a ref code, A, C, G and T, lay down cyan, magenta, yellow and black. A heterozygous A/G base prints cyan and yellow, green.

In Python

from gpxiltools.palettes import describe

for p in describe():
    print(p["name"], p["srgb"]["A"], p["cmyk_percent"]["A"], "–", p["description"])
