Add an annotation plane

gpxil annotate copies a gpxil file with an annotation as a plane of its own: RepeatMasker’s repeats, a BED file’s genes or regions, a bedGraph’s signal. The plane has a value at every base, like the genome’s own planes, so it lines up with the genome base for base and goes wherever the file goes: the Viewer draws it, Python reads it, and a working copy of a region cuts it out with the rest.

What a base holds

a label
From a RepeatMasker table, the repeat over the base: its family by default (SINE/Alu, LINE/L1, Satellite/centr …), or its class (SINE), or its name (SINE/Alu/AluSx). From a BED file with names, the feature’s name. Each label is a number, 1, 2, 3 … in the order of their names, 0 where there is no feature, and the plane’s metadata keeps the labels: 8-bit numbers for up to 255 labels, 16-bit for more.
where a feature is
1 there, 0 elsewhere: a BED file without names, or any file, as presence.
a score or a value
A feature’s score (a repeat’s divergence from its family’s consensus, in %), or a bedGraph’s value – replication timing, a Hi-C compartment’s eigenvector, any signal – as a 32-bit floating-point number, and NaN where there is none.
where features overlap
The shorter one is drawn, so a repeat inside another shows; of two as long, the later in the file.

The plane is an extension plane of the gpxil specification (section 5.6): its name is x- and letters, digits, - or _, and readers that don’t know it pass it by. The file’s own planes are copied as they are stored, without decoding them, so a chromosome takes a few seconds, and the plane adds little: chromosome 17’s repeats add 0.7 MB to its 24.6 MB. In a file of windows, each window gets the features over its own stretch of the chromosome.

The form

The gpxil file
Any gpxil file, with its reference plane or without.
The annotation
A RepeatMasker table (UCSC’s rmsk table, or RepeatMasker’s .out), a BED file or a bedGraph file, plain or gzipped.
The plane’s name
x-repeats for repeats, else x- and the file’s name.
A base holds; a repeat’s label
What fits the file, to begin with: labels for a RepeatMasker table or a BED file with names, values for a bedGraph. A repeat’s label is its family, unless you choose its class or name.
Only features whose name matches, of at least this many bases
As in Stack features.
What it holds; the values’ units
Kept in the plane’s metadata: said from the file if you leave them empty.
Make the plane again if the file has it
Otherwise a file that has the plane already is refused.
Save the copy as
A new file, ~/genomes/HG002_chr17.repeats.gpxil.tif for the first example: the tool never changes the file it copies.

What it gives

The copy, and a line saying what was added: the plane, what its bases hold, how many labels, and how many bases have a feature. Chromosome 17’s repeats give 58 labels over 43,047,843 bases, half the chromosome. Look at it in the Viewer opens the plane’s own view: each label in a colour of its own, a repeat class in one hue – SINE red, LINE blue, LTR teal, DNA transposons yellow, simple repeats violet, low-complexity sequence pink, satellites green – its families in lighter and darker shades of it, and paper where there is no feature. Point at a base to read its label. A plane of values is drawn from light to dark blue over the range in view. Any annotation plane of a file is in the Viewer’s Show list.

Once the first button has made the copy, look at the repeats around a GA-sequence that began as an Alu element’s tail: an AluJb, then a run of AGAA repeated, which RepeatMasker calls a simple repeat.

In the terminal

gpxil annotate /data/examples/HG002_chr17.gpxil.tif /data/examples/rmsk_chr17.txt.gz --plane x-repeats -o ~/genomes/HG002_chr17.repeats.gpxil.tif
gpxil annotate ~/genomes/HG002_chr17.repeats.gpxil.tif /data/examples/rmsk_chr17.txt.gz --plane x-repeat-age --as score --units % \
    -o ~/genomes/HG002_chr17.repeats-age.gpxil.tif
gpxil info ~/genomes/HG002_chr17.repeats-age.gpxil.tif
viewer ~/genomes/HG002_chr17.repeats.gpxil.tif chr17:6,792,801-6,793,400 --plane=x-repeats

A second plane goes on the copy that has the first. gpxil subset … --planes ref,gt,flags,x-repeats keeps planes by name, and gpxil validate checks the new file.

In Python

from gpxiltools import GpxilFile
from gpxiltools.annotate import annotate

summary = annotate("/data/examples/HG002_chr17.gpxil.tif", "/home/user/genomes/HG002_repeats.gpxil.tif",
                   "/data/examples/rmsk_chr17.txt.gz", plane="x-repeats", log=lambda msg: None)
print(summary["labels"], "labels over", summary["bases_with_a_feature"], "bases")
with GpxilFile("/home/user/genomes/HG002_repeats.gpxil.tif") as g:
    labels = g.metadata["planes"]["x-repeats"]["labels"]   # value -> label
    values = g["chr17"].read("x-repeats", 6_792_900, 6_793_300)
print(sorted({labels[str(v)] for v in values.tolist() if v}))
