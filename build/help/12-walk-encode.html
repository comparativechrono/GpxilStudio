Turn someone’s VCF into a gpxil file

A VCF file lists where a person differs from the reference. A gpxil file holds the whole of each chromosome, base by base, with the person’s genotype at every base. This walkthrough makes one from HG002’s variants around TP53, with chromosome 17 of GRCh38 as the reference, read from the web. Then it makes the same file without the reference’s bases, which is a hundred times smaller, and finally the specification’s worked example from a FASTA file.

What you need

  • The person’s variants: a VCF file (.vcf or .vcf.gz) with their genotypes. A VCF of several people is fine: you choose which one to encode.
  • The reference the variants were called against: a FASTA file, or a gpxil file with its reference plane, such as the chromosomes of GRCh38 in /data/grch38. Contig names are matched with or without chr, so 17 in a VCF finds chr17.
  • If you have one, a BED file of the regions called with confidence. Benchmark VCFs such as Genome in a Bottle’s come with one, and so do many variant callers’ outputs (as a gVCF, or a coverage BED).

1 · The variants

HG002_TP53.vcf holds the 206 records of the Genome in a Bottle benchmark (version 4.2.1) for HG002 between chr17:7,600,001 and chr17:7,750,000, around TP53. Open it to see what a VCF looks like: one line for each place where HG002 differs from the reference, with his genotype, such as 0/1 (one copy) or 1/1 (both).

2 · Why the regions called with confidence matter

A VCF lists the bases where a person differs from the reference, but says nothing about the rest. Some of the rest is like the reference; some wasn’t sequenced well enough to tell. Without more information, the encoder can only assume the person has the reference everywhere else – across the whole of chromosome 17, in this case, which this VCF can’t possibly tell us.

HG002_TP53.bed lists the 52 stretches, 140,254 bases in all, where the benchmark is confident of HG002’s genotype. With it, bases outside those stretches become UNKNOWN (no call) rather than the reference, so the gpxil file says exactly what is known and no more.

3 · Encode it

Make a gpxil file (encode) with the VCF, the BED file and chromosome 17 of GRCh38. The reference file holds only chromosome 17, so only chromosome 17 is encoded; with a reference of the whole genome, you’d put chr17 in Only these contigs.

Press Run. Python reads chromosome 17’s 83 million bases from the web (about 23 MB), applies each of the 206 records base by base, and writes ~/genomes/HG002_TP53.gpxil.tif: about 23 MB, almost all of it the reference plane. It takes about a minute on a desktop computer, longer on a phone, and about half a gigabyte of memory, because the encoder holds the whole chromosome’s planes while it works (the same command takes about 12 seconds on a computer’s own Python). The note under the result says how many contigs and bases it wrote.

The settings you’ll most often change:

Planes from the VCF
The genotype and flags planes (gt, flags) are all that sequences, pictures and VCF need. A VCF’s genotype qualities, read depths and phase sets can go in too (gq, dp, ps), but they take as much memory again.
Sex chromosomes
For a man’s VCF, XY gives chromosomes X and Y one copy outside the pseudo-autosomal regions, so his second haplotype is ABSENT there rather than a copy of the first.
Sample
The VCF column to encode, if it has several.

Make a gpxil file describes every setting.

4 · Check it and look at it

In the Viewer, the 150,000 bases around TP53 are faded reference where they were called with confidence, with HG002’s variants in orange and red, and grey (unknown) between and around the stretches of the BED file – as is the whole of the rest of the chromosome.

5 · The same, without the reference

The reference plane takes up nearly all of the file, and it is the same for everyone. Encode again without it, with Leave out the reference plane ticked: the file, ~/genomes/HG002_TP53.noref.gpxil.tif, is about 0.2 MB instead of 23. It names its reference by the checksums of its sequences, so the reference can be found and checked later.

The button ticks Leave out the reference plane for you, and the name under Save as changes to match; press Run. Anything that needs the bases themselves then needs the reference too. The tools that read bases show a field for it, Its reference, and fill in the GRCh38 chromosome from /data/grch38; gpxil checks it against the file’s checksums. The Viewer does the same by itself for a file made on GRCh38. Use files without the reference to keep many people’s genomes small, or to send one; keep the reference with the file when it has to stand on its own.

6 · From a FASTA file: the worked example

The specification’s worked example is a reference of ten bases (worked-example.fa) and four variants (worked-example.vcf). Encode it with 4 bases per row, as in the specification, and each plane is a picture of 3 rows of 4 pixels, which you can read pixel by pixel in The codes.

The button sets Bases per row of each page to 4. A FASTA file is read whole, one record at a time, so for a whole human genome use a gpxil reference, or work on your own computer.

Your own data

  • Add your VCF, and its BED file, with the Files tab’s ↑ button, or by dragging them onto it. They go into the folder you choose, such as ~/genomes.
  • For a VCF on GRCh38, give the chromosome you want from /data/grch38 as the reference, and encode one chromosome at a time. Each takes about 6 bytes of memory a base: half a gigabyte for chromosome 17, about 1.5 GB for chromosome 1, which is more than a browser tab may have.
  • For the biggest chromosomes, or a whole genome in one file, work on your own computer, where gpxil can use the whole-genome reference file from the Gpxil browser’s downloads (The GRCh38 reference, On your own computer).

The same in the terminal

gpxil encode /data/grch38/chr17.gpxil.tif -v /data/examples/HG002_TP53.vcf --callable /data/examples/HG002_TP53.bed --planes gt,flags -o ~/genomes/HG002_TP53.gpxil.tif
gpxil validate ~/genomes/HG002_TP53.gpxil.tif
gpxil encode /data/grch38/chr17.gpxil.tif -v /data/examples/HG002_TP53.vcf --callable /data/examples/HG002_TP53.bed --planes gt,flags --no-ref -o ~/genomes/HG002_TP53.noref.gpxil.tif
ls -l ~/genomes
gpxil fasta ~/genomes/HG002_TP53.noref.gpxil.tif --which 1 --region chr17:7676101-7676200 --reference /data/grch38/chr17.gpxil.tif

The last command needs the reference to spell out HG002’s first haplotype from the file without one.

The same in Python

from gpxiltools.encode import encode

summary = encode("/data/examples/worked-example.fa", "/home/user/genomes/worked-example.gpxil.tif",
                 vcf="/data/examples/worked-example.vcf", width=4)
print(summary["contigs"], "contig,", summary["bases"], "bases,", summary["bytes"], "bytes")
