The views and their colours

Each view of the Viewer draws one or two planes of the file. The key under the picture names its colours; this page says what each one means. The first four views are exactly what gpxil render draws, pixel for pixel, in every palette, so a picture you like in the Viewer can be made as a file with the command under it.

Reference bases

The ref plane: each base in the palette’s colour (in the classic palette, A red, C blue, G green, T yellow). Bases in soft-masked repeats – lower case in the reference – are 45 % paler, except in the GPxI greys, which need all their levels. An ambiguous base is the mix of its bases’ colours. N, a base that isn’t known, has a colour that no base and no mix of bases has – near-black in the classic and Okabe–Ito colours, light blue in the GPxI greys, grey in the process inks – and is never paler. A gap, where there is no base, is the colour of paper.

Genotype

Each base as the person has it, both haplotypes at once, as one IUPAC code (The codes). Where the haplotypes agree, the base’s colour; where they differ, the mix of their two colours, so a heterozygous A/G base has the colour of R, half red and half green. A haplotype that wasn’t called, or that has a complex variant, counts as N, so its base is N’s colour: near-black in the classic colours. A base deleted from one haplotype shows the other haplotype’s base – so look for deletions in the next two views – and a base deleted from both is paper. Soft-masked bases stay paler, as in the reference.

The key lists the colours in view, with each heterozygous pair that is there – A and G, C and T and so on – and how many bases have it. In TP53, HG002 is heterozygous at only three bases, all of them A and G; in the 150,000 bases around it, every pair turns up. Some mixes are greys – in the classic colours, C and T mix to mid-grey – which is why N is near-black: a heterozygous base never looks like one that isn’t known. To see every heterozygous base in one colour, use the Variants view, where they are all orange.

Haplotypes

The two haplotypes separately, as two rows of pixels for each row of bases: haplotype 1 above, haplotype 2 below. Each pixel is that haplotype’s own base: a substitution in its new base’s colour, a deleted base paper (as is haplotype 2 where the person has only one copy), and a base that wasn’t called, or a complex variant, N’s colour (near-black in the classic colours). A heterozygous variant shows in one row and not the other; a homozygous one in both.

Variants

The quickest way to find variants: the reference is faded 80 % towards white, and the bases where the person differs from it are coloured by what kind of change it is.

ColourMeaning
orangeheterozygous: a substitution on one haplotype and the reference on the other, or a different substitution on each
redhomozygous: the same substitution on both haplotypes, or on the only copy where the person has one
near blackdeleted, on either haplotype
greenan insertion follows this base, on either haplotype
greynot called, on either haplotype
purplea complex variant, which can’t be written base by base, such as an inversion
fadedthe same as the reference

A base can be more than one of these: then purple wins, then green, then near black, and grey shows only where nothing else does.

Flags

The flags plane, one colour for the most telling flag of each base:

ColourMeaning
redFILTERED: a call over this base didn’t pass its filters
greenINS1 or INS2: an insertion follows this base
blueVARIANT_SITE and PHASED: a phased call covers this base
grey-blueVARIANT_SITE: a call covers this base (any genotype, the reference’s too)
pale bluePHASED alone
whiteno flags: the base is as it is by default, not because a call said so

These are the colours the file’s own colour map gives its flags pages, so an ordinary image viewer shows them the same way.

Genotype quality, read depth

The gq and dp planes, from white for 0 to deep blue for 99 or more (genotype quality) or 60 or more (read depth). Pink means the value isn’t known (255): a base that no call with that field covers.

Phase sets

The ps plane: each phase set in a colour of its own, and white where a base is in none. Within one phase set, haplotype 1 is the same parental copy throughout; between phase sets, it may not be.

The same in a file

For the reference, genotype, haplotypes and variants views, the command under the picture is the gpxil render that makes the same picture as a file, with the same bases per row, pixels per base and palette (Draw a region as a picture). gpxil render can also mark the bases that insertions follow in the haplotypes view (--mark-insertions), lay a region out along a Hilbert curve, and write CMYK for print. The flags, quality, depth and phase-set views are the Viewer’s own: under them, a Python cell reads the plane’s values as a NumPy array, ready to add to the notebook. The codes describes the values behind every colour.
