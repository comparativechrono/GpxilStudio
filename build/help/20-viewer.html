The Viewer

The Viewer shows a gpxil file as it is: one pixel, or a square of pixels, for each base, in rows that read from left to right and from top to bottom like a page of text. It reads only the part of the file it shows, straight from the file, without Python, so a whole genome opens at once – even one on the web.

Choosing what to see

File
Any gpxil file: yours, the examples, or a chromosome of the GRCh38 reference, read from the Gpxil browser. Add a file… puts one from your computer into ~/genomes and opens it; it stays in this browser.
Region
Choose a contig, or type a region and press Go (or Enter): chr17:7,661,779-7,687,546, counting from 1 and including both ends, with or without the commas. A contig’s name alone means all of it, and one position, such as chr17:7676154, that base.
Show
What to draw: the reference’s bases, the person’s genotype, their two haplotypes, their variants, or the flags, genotype quality, read depth or phase sets. Only the views the file can show are offered: a file without a sample has only the reference. The views and their colours
Colours
One of gpxil’s palettes: classic, Okabe–Ito (safe for colour-blind readers), the GPxI greys, or the process inks (The palettes).

A file opens at TP53 if it has chromosome 17, and otherwise at the middle 100,000 bases of its first contig. The Viewer remembers the file, region, view and colours you had last time.

Moving around

  • The arrow buttons move left and right by half the view; the magnifier zooms in to half as many bases, and − zooms out to twice as many.
  • Double-click a base to zoom in around it.
  • Click the picture, and then the keys ← and → move by a quarter of the view, + and − zoom.

The picture is as wide as the tab: as many bases a row as fit, at 1 to 24 pixels a base, so a small region shows big squares and a large one single pixels. The line above the picture gives the region, the number of bases, how many a row and how many pixels each. The Viewer draws at most 4 million bases at once; a bigger region shows its first 4 million.

Pointing at a base

Point at a pixel, and the line under the picture says what the file holds there: the position, the reference’s base (and whether it is soft-masked), each haplotype’s state and the gt value they make, the flags, the genotype quality, the read depth and the phase set. At HG002’s chr17:7,676,154, for example: reference G, haplotype 1 C, haplotype 2 C (gt 34), flags VARIANT_SITE, GQ 254, DP 254. The codes explains every value.

Keeping what you see

Under the picture is the gpxil render command that draws the same picture, pixel for pixel, as a file, ready to run in the terminal; Save the picture saves the view as it is, as a PNG in ~/results. For the flags, quality, depth and phase-set views, which gpxil render doesn’t draw, there’s a Python cell instead, which reads the plane’s values for the region as a NumPy array: Add to notebook puts it in the open notebook.

Files on the web, and files without a reference

A file on the web, such as GRCh38’s chromosomes in /data/grch38, is read a piece at a time as you move around: the first view of a chromosome takes a moment, and parts you’ve seen are kept for a while. A file written without its reference plane (--no-ref) has only the person’s genotype; if its metadata says its reference is GRCh38, the Viewer reads the bases from /data/grch38 and says so above the picture.

From the terminal

viewer FILE [REGION] opens a file in the Viewer from the terminal, with --plane=gt (or ref, flags, gq, dp, ps) for a view:

viewer /data/examples/HG002_chr17.gpxil.tif chr17:7,661,779-7,687,546
viewer /data/grch38/chr21.gpxil.tif chr21:30,000,001-30,500,000 --plane=ref
