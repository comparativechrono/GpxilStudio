Versions, and how to cite

These are the versions that this copy of the studio runs. When you report work done with it, say which versions you used. The files record them too: a gpxil file names the program that wrote it in its metadata ("generator": "gpxiltools 0.7.0"), with the version of the specification it follows, and a pxil file does the same.

Python itself is Pyodide 0.29.5 (Python 3.13), with NumPy 2.2.5, Pillow 11.3.0 and jsonschema 4.23.0 as Pyodide builds them, downloaded from jsDelivr the first time Python starts; matplotlib 3.8.4 follows in the background, for plots. To see what you have, type python --version or pip list in the terminal, or help, which gives the programs’ versions once Python has started.

The packages

  • gpxiltools 0.8.2 reads gpxil files on web servers a piece at a time (with HTTP range requests), takes a gpxil file as the reference, such as a chromosome of GRCh38 from the Gpxil browser, writes VCF of chosen regions (gpxil vcf --region), and runs without imagecodecs, which Pyodide doesn’t have: all new in 0.3.0. 0.3.1 gives N, a base that isn’t known, a colour that no base or mix of bases has: near-black in the classic and Okabe–Ito palettes, where it was a grey that a heterozygous C/T base shared. 0.4.0 adds gpxil subset, working copies of some contigs and planes made without decoding, and gpxil stats, the counts of what a file holds. 0.5.0 adds gpxil compare: two genomes base by base, and a child with both parents. 0.6.0 writes version 0.2 of the gpxil specification, in which unphased calls that overlap go one to each haplotype rather than running together on one, and has the reader of gpxil files in JavaScript that the Viewer and the Files tab use, the same as the Gpxil browser’s. 0.7.0 writes version 0.3, which adds windows: contigs that hold a stretch of a chromosome and keep its positions. gpxil subset cuts a region out as one, gpxil encode --region makes one straight from a VCF, and every command, the JavaScript reader and the Viewer read them at the chromosome’s positions. 0.8.0 adds six tools that look for patterns: runs of a composition (gpxil runs), repeats wrapped at their period (gpxil period), features stacked and lined up (gpxil stack), substitution spectra matched by context (gpxil spectrum), annotation planes from BED or RepeatMasker files (gpxil annotate) and strand-symmetry maps (gpxil skew). 0.8.1 takes a repeat’s class and family from its table, so repeats whose own names hold a slash are labelled rightly. 0.8.2 reads a person’s haplotypes faster: a contig’s inserted sequences are decoded once, not for every region read.
  • gpxil2pxil 0.2.0 makes pxil pictures of genes, transcripts and proteins from a gpxil genome, from the reference or from either of a person’s haplotypes, with the genes of Ensembl from the Gpxil browser’s files or from a GTF file, and says how a person’s protein differs from the reference’s. 0.2.0 finds a gene in a window that holds it.
  • pxil 0.1.1 reads and writes pxil files, and has a command, pxil, that prints them as FASTA. 0.1.1 colours N near-black, as gpxiltools does.
  • gpxilwb 1.1.0 is the studio’s own runner, which joins the page to the packages. You don’t need it anywhere else.

The studio’s copies of gpxiltools, gpxil2pxil and pxil are their releases on PyPI, unchanged, so pip install gpxiltools gpxil2pxil pxil on your own computer gives exactly the code that runs here (On your own computer). The formats have versions too: the examples here follow version 0.2 of the gpxil specification, except the TP53 window, which follows 0.3 (the first with windows), and the GRCh38 reference’s files, which hold no person, version 0.1 (the three differ only in how a person’s calls are written, and in windows); pxil files follow version 0.1 of the pxil specification.

The data

  • The GRCh38 reference in /data/grch38 is the Gpxil browser’s: the primary assembly of GRCh38 from Ensembl release 116, soft-masked, with Ensembl 116’s genes and transcripts.
  • HG002 in the examples is the Genome in a Bottle benchmark for HG002, version 4.2.1 on GRCh38, with its regions called with confidence; HG003 and HG004, his father and mother, are their version 4.2.1 benchmarks, and HG002_chr17_v5.0q is HG002’s newer benchmark, version 5.0q. Cite Zook et al. 2016 and Wagner et al. 2022 if you use them, and Hansen et al. 2026 for version 5.0q.
