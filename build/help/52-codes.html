The codes

A gpxil file holds numbers, not colours. This page gives the meaning of every number in the three main planes – the reference (ref), the genotype (gt) and the flags – and then works through the specification’s example, pixel by pixel.

ref: the reference base

One byte a base. Its low four bits are the base as a set of A, C, G and T, one bit each: A 1, C 2, G 4, T 8. So an ambiguity code is the sum of its bases – R, A or G, is 1 + 4 = 5 – and N, any base, is 15. These are the codes BAM files use for bases. 0 means no base (a gap). The next bit, 16, marks a soft-masked base: one written in lower case in the reference’s FASTA file, because it lies in a repeat.

Add 16 for a soft-masked base: a is 17, c 18, n 31. So a ref byte is 0 to 15, or 17 to 31.

gt: the genotype

One byte a base. Its high four bits are what haplotype 1 has there, its low four bits what haplotype 2 has: the byte is haplotype 1 × 16 + haplotype 2. In hexadecimal, that makes the first digit haplotype 1 and the second haplotype 2. Each haplotype’s state is relative to the reference base:

StateNameThe haplotype…
0REFhas the reference base
1, 2, 4, 8A, C, G, Thas this base instead (the same bits as in ref)
10 (hex A)ABSENTdoesn’t exist here: the person has one copy, as a man has of most of X and Y
12 (hex C)COMPLEXhas something that can’t be written base by base, described in the sidecar
13 (hex D)DELhas lost this base: it is deleted
15 (hex F)UNKNOWNwasn’t called, so isn’t known

The other values are reserved, and readers treat them as UNKNOWN. The special states’ letters are reminders: Absent, Complex, Deleted, and F – all four bits – for unknown, as N is all four bits in ref. A haplotype that has the reference base is always REF, never the base itself, so a base state always means a change.

Insertions aren’t states: they happen between bases. The base an insertion follows is flagged (below), and the inserted bases are in the sidecar (The gpxil format).

flags

One byte a base. Each bit is a flag, and a base can have several:

BitNameMeaning
1PHASEDthe call over this base was phased (0|1), so haplotypes 1 and 2 are the two parental copies, not just two alleles
2INS1an insertion follows this base on haplotype 1
4INS2an insertion follows this base on haplotype 2
8FILTEREDa call over this base didn’t pass its filters: its FILTER was neither PASS nor .
16VARIANT_SITEa call covers this base, whatever its genotype

VARIANT_SITE tells “the VCF said this base is the reference” (REF, with the flag) from “the reference, because the VCF said nothing” (REF, without it). Bits 32, 64 and 128 are reserved, and always 0.

The other planes

gq and dp hold the genotype quality and read depth of the call over each base, from 0 to 254 (bigger values are stored as 254), and 255 where no call with that field covers the base. ps holds the phase set of the phased call over each base, as a 32-bit number, and 0 where the base isn’t phased.

The worked example, pixel by pixel

The specification’s example has a reference of ten bases, ACGTACGTac – the last two soft-masked – and four calls:

Spell each haplotype out base by base – REF gives the reference’s base, a change its own base, DEL nothing and UNKNOWN N, with each insertion after its base – and haplotype 1 is ACGTGTGGnc, haplotype 2 ATGTACGTGGgc, keeping the reference’s lower case. The genotype as one sequence of IUPAC codes, the bases of both haplotypes together, is AYGTACGTNc: Y, C or T, at offset 1, and N at offset 8, where haplotype 1 isn’t known. With 4 bases a row, each plane is a picture of 3 rows of 4 pixels, the last two of them padding.

In Python

from gpxiltools import GpxilFile
from gpxiltools import codes as C

with GpxilFile("/data/examples/worked-example.gpxil.tif") as g:
    c = g["chrT"]
    ref, gt, flags = c.read("ref"), c.read("gt"), c.read("flags")
    print(c.sequence(), ref.tolist(), gt.tolist(), flags.tolist())
    for i in range(c.length):
        names = [name for bit, name in C.FLAG_NAMES.items() if flags[i] & bit]
        print(i, c.sequence(i, i + 1), C.describe_gt_byte(int(gt[i])), names)
    print(C.IUPAC[C.genotype_iupac(ref, gt)[1]])   # C on haplotype 1, T on haplotype 2: Y
    print(c.image("ref"))                          # as stored: 3 rows of 4, with the padding
    print(c.sidecar())
